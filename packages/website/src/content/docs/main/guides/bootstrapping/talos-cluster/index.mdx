# Bootstrap Talos and Karpenter on AWS

Use `aws_kube_talos` for the control plane and `kube_aws_ccm` for the AWS cloud controller manager (CCM). Use Karpenter for workers. Start with a temporary public load balancer. Remove it after you verify private access.

## 1. Prepare the control plane

1. Choose a private subnet and a fixed controller IP. Reserve a private API DNS name.
2. Verify that the VPC has a tagged public subnet in the bootstrap controller's Availability Zone.
3. Generate a new Talos secrets bundle. Encrypt the file with SOPS. Use a separate state key for the cluster.
4. Pass the VPC, subnet, IP, API DNS name, and encrypted secrets to `aws_kube_talos`. Keep controller public IPs disabled.

## 2. Apply Talos with temporary public access

Set `talos_access_transport = "bootstrap_public"`. The module detects the runner's public IPv4 address and opens the two API ports to its `/32`. Set `bootstrap_public.operator_cidr` if the runner uses a different egress address.

1. Review and apply the Talos plan. Save `kubeconfig` and `talosconfig` in private files.
2. Use `bootstrap_public_kube_url` and `bootstrap_public_talos_endpoint` to check `/readyz` and the etcd members.

## 3. Install networking and switch to private access

1. Apply `kube_cilium`. Pass `cluster = { type = "talos", name = dependency.cluster.outputs.cluster_name }`. Use its default Talos KubePrism endpoint.
2. Apply `kube_aws_ccm`. Pass the `cluster` and `controller_provider_ids` outputs of `aws_kube_talos`. It sets the controller provider IDs and installs CCM. Kubernetes `1.36` defaults to CCM `v1.36.1`. Set `image_version` to override it. Use the same Kubernetes major and the target minor or the previous minor. During an upgrade, keep CCM at or below the oldest API server minor that it can reach. [AWS CCM compatibility](https://cloud-provider-aws.sigs.k8s.io/#compatibility-with-kubernetes) · [Kubernetes version skew](https://kubernetes.io/releases/version-skew-policy/#kube-controller-manager-kube-scheduler-and-cloud-controller-manager)
3. Apply `kube_core_dns`. Set `service_ip` from the Talos `dns_service_ip` output. Check DNS from a Pod.
4. Configure Headscale or Tailscale. Route the private controller subnets and make the private API name resolvable from the runner.
5. Verify authenticated Kubernetes and Talos API requests over the private path. Set `talos_access_transport = "vpn"`. Plan and apply with the public load balancer still available.
6. Repeat those checks. Set `bootstrap_public = { enabled = false }`. Review the removal plan and apply it. Verify that the private APIs still work.

Use separate plans for the transport change and the load balancer removal.

## 4. Install Karpenter

Apply cert-manager and the AWS Pod Identity webhook. Verify AWS STS access with a Pod that uses an annotated service account.

For a first install, render the CRDs with the same chart version as the controller. Add the Helm ownership labels before you apply them. The Talos controller defaults to version `1.15.1`. [Karpenter compatibility](https://karpenter.sh/docs/upgrading/compatibility/)

```sh
karpenter_crds=$(mktemp)
helm template karpenter-crd oci://public.ecr.aws/karpenter/karpenter-crd \
  --version 1.15.1 --namespace karpenter --include-crds |
  kubectl annotate --local -f - -o json \
    meta.helm.sh/release-name=karpenter-crd \
    meta.helm.sh/release-namespace=karpenter |
  jq -s '{apiVersion: "v1", kind: "List",
    items: map(.metadata.labels."app.kubernetes.io/managed-by" = "Helm")}' > "$karpenter_crds"
kubectl apply --server-side --dry-run=server -f "$karpenter_crds"
kubectl apply --server-side -f "$karpenter_crds"
```

In `kube_karpenter`, pass `cluster = dependency.cluster.outputs.cluster`. This selects Talos and creates worker IAM. Pass the VPC ID to scope launch permissions. Use `talos_worker_identity` for optional IAM naming and ECR cache settings.

If the cluster uses EC2 or STS VPC endpoints, set `ip_restrictions_enabled = false` for Karpenter. AWS omits `aws:SourceIp` on requests through these endpoints. [AWS IAM condition keys](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_condition-keys.html#condition-keys-sourceip)

## 5. Apply worker pools

Set these three inputs in `kube_karpenter_node_pools`.

| Input | Value |
| --- | --- |
| `talos_launch` | Talos AMI and node security group, VPC ID, and selected private subnets. |
| `talos_worker_bootstrap` | Talos `node_bootstrap` output plus `secrets_bundle` with only the public CAs and worker join credentials. |
| `node_instance_profile` | Output of the Karpenter caller. |

Use the encrypted Talos secrets file for the join credentials. Keep control-plane signing keys out of worker inputs. The worker installer tag must match `talos_version`.

Install EBS CSI before you enable its startup taint. Make sure Cilium tolerates the taint. Schedule a Pod that tolerates the worker taints. Check that Karpenter launches a worker, its provider ID matches the EC2 instance, and both the node and Pod become `Ready`.

## Upgrade older callers

Move the worker role, instance profile, ECR read policy, and optional cache import policy from Talos state to Karpenter state. Keep their AWS identities. Take versioned state backups and pause applies until both states are verified.

| Legacy Talos address | Karpenter address |
| --- | --- |
| `aws_iam_role.worker` | `aws_iam_role.talos_worker[0]` |
| `aws_iam_instance_profile.worker` | `aws_iam_instance_profile.talos_worker[0]` |
| `aws_iam_role_policy.ecr_read` | `aws_iam_role_policy.talos_worker_ecr_read[0]` |
| `aws_iam_role_policy.cache_import[0]` | `aws_iam_role_policy.talos_worker_cache_import[0]` |

Transfer the bindings before you apply either module. Check that the plan retains the original profile and policies. Existing controller identities stay in Talos. Use `controller_identity` for controller settings.
